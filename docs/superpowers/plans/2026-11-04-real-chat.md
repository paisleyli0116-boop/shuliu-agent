# ShuLiu Desktop Real Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable a manually triggered, text-only Desktop chat through the configured Python Model Gateway without fake messages or bypassing safety checks.

**Architecture:** Renderer maintains one temporary in-memory transcript and calls a typed Preload API. Electron Main validates the request and forwards it over the existing Sidecar IPC allowlist. Python validates the selected enabled profile and builds trusted Gateway context before invoking the existing Model Gateway with Policy, SecretRef, health, a bounded process-local request allowance, a 512-token output cap, and fallback disabled.

**Tech Stack:** React, TypeScript, Electron IPC/contextBridge, Python Sidecar NDJSON, Model Gateway, LiteLLM adapter, pytest, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-04-real-chat-design.md`

## Global Constraints

- Renderer does not access databases, secrets, or providers directly.
- Only an explicit Send action can call a Provider.
- Provider credentials stay in OS secure storage and are resolved only by the Gateway.
- The Gateway is the only Provider execution path; Policy, budget, health, SecretRef, and no-fallback checks remain active.
- Chat content is not written to logs or persistence in this slice.
- No real Provider request is run by tests or by the implementation session.
- No change to Git `main`, no commit, and no push.

## Review Focus

- Malformed or oversized chat payloads: reject before Gateway entry.
- Unconfigured/disabled profile or unsupported capability: safe failure and no Provider invocation.
- Safe Mode or IPC unavailable: do not send and do not claim a response.
- Repeated or concurrent request ID: no second Provider invocation.
- Renderer restart: no hidden automatic replay or misleading persisted history.
