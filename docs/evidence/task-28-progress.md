## Implementation summary

- Added strict provider-profile parsing. Profiles contain a SecretRef, never a plaintext key; unknown credential-bearing fields are rejected. Secret-shaped model identifiers are rejected before they can be emitted in connection evidence or command output. A 32-character contiguous identifier component is rejected as a conservative opaque-token guard; custom IDs using such a component are a compatibility limitation.
- Added provider-specific real connection checks through the existing Model Gateway and policy path. The check is an explicit, bounded canary, uses the configured SecretResolver, has no provider fallback, limits process-local probes to three and output tokens to eight, and returns safe status/error fields. The probe counter is process-local and resets when the worker restarts; durable usage accounting remains a follow-up boundary.
- Connected Desktop provider settings and fixed allowlisted IPC methods to the Python Sidecar. The key input is cleared after submission, and UI/IPC errors do not return raw secrets or provider exception text. No success is hardcoded in the Desktop layer.
- Extended Windows frozen-Sidecar packaging to include the Windows Credential Manager backend explicitly. Added a release-evidence schema for real-provider results; schema evidence cannot claim `real_provider` success from a fake provider.
- No dependency or lockfile updates. No API key, token, or private credential was written to the repository.
